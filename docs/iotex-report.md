# IoTeX 交易结构复核报告

**更新时间: 2026-04-16**

**核心结论**

- IoTeX 在 `2026-04-12` 当天的交易活跃度，主要不是自然用户行为，而是协议系统动作与自动化任务网络。
  - 其中 `87.23%` 是零费 `GrantReward` 型系统交易
  - 剔除系统交易后，剩余付费交易的 `78.18%` 又高度集中在两个疑似自动化调用的合约方法。
- 但在 DePIN / Physical AI 场景下，这类自动化交易本身并不应被简单等同于“刷量”或“伪造活跃”。更准确的表述是：IoTeX 这组高交易数主要反映协议结算、设备协作与机器网络运转强度，而不是自然用户交互强度。

### 目的、方法与数据来源

针对 IoTeX 在 24 小时内的链上交易数据，复核其主要来源是来自真实用户行为，还是主要来自协议系统动作与自动化任务网络。
1. 以 Dune 的 `2026-04-12` 作为日度口径参考，用 IoTeX 官方 RPC 与区块浏览器/API 复核当日完整交易，并与 Dune 的数据进行对比。
2. 按交易类型拆分系统动作与普通交易，识别出零费用 `GrantReward` 型系统交易；同时对照区块数，验证其与出块节奏高度绑定。
3. 对剩余付费交易按目标地址、调用方法、发送节奏和合约业务做分组归因。
4. 对 `GrantReward / 0-gas` 的 `36` 个发送方，进一步调用 IoTeXScan 官方 `account/txlist` API 复核逐地址发送频率与时间分布。

**结构判断**

- 从区块分布看，这类 `GrantReward / 0-gas` 系统交易在样本窗口内的每个区块都能见到，指向同一个系统合约地址 `0xa576c141e5659137ddda4223d209d4744b2106be`，且由 `36` 个不同地址发送。
- 这 `36` 个发送方的相邻两笔交易中位间隔全部为 `60 秒`；换算成块间隔为 `24` 个块。
- 官方文档 [Voters and Delegates](https://docs.iotex.io/blockchain/learn-iotex/core-concepts/voters-and-delegates) 写明，前 `36` 名 `Consensus Delegates` 负责交易验证和出块；
- 这些发送方使用同一组 `GrantReward` 类型交易发送到统一合约地址，不携带普通转账金额字段，更像在链上更新奖励状态或将奖励记入奖励池/奖励账户。

- 这说明把系统交易剔掉之后，IoTeX 的剩余活跃也不是“分散的自然用户使用”，而是仍以少数自动化行为组为主。

### 综述

- 如果把系统交易单独拿出来看，IoTeX 这一天的大部分链上活动其实是“协议奖励相关动作”，而不是普通用户转账。
- 如果把系统交易剔掉再看，剩余交易里也有非常大的比例来自少数重复任务组，特别是 `ioSwarm` 奖励池结算相关的 `depositSettleAndClaim(address[],uint256[],address[])` 和 `Native Staking` 相关的 `depositToStake(uint64,uint256,uint8[])` 两组。
- 真正相对更像自然用户活动的是 `native-transfer` 那一小层，但规模只有 `403` 笔，只占总交易的 `1.02%`。
- 因此，这个链上活跃画像更接近“系统奖励 + 自动化任务网络”，而不是“高频真实用户生态”；但在 DePIN 语境下，这不宜被直接表述为“刷量”，而应理解为“机器网络活跃度高于自然用户交互活跃度”。

### 说明

- `AgentRewardPool` 是 IoTeX 区块链上的一个特定智能合约，主要用于管理和分配其去中心化 AI 和基于 Agent 的生态系统（例如 `ioSwarm`）中的奖励。
- `ioSwarm` 是 IoTeX 推出的去中心化 AI 执行层，它通过将传统的重型节点转化为数百万个基于 gRPC 协议、具备 `ioID` 身份的轻量级 Agents，实现机器智能在物联网设备上的分布式协作与自动化任务验证。参与者通过运行这些代理节点，可以赚取 `$IOTX` 代币奖励，而 `AgentRewardPool` 合约正是用于管理这些奖励分发的。
- Dune 在本报告中的作用，仅是提供日期口径和日度汇总指标参考，用来与官方链上数据做交叉核实；具体交易结构、方法调用和地址行为分析，全部以 IoTeX 官方 RPC 与区块浏览器/API 数据为准。
- `GrantReward / 0-gas` 发送频率复核，使用的是 IoTeXScan 官方 `account/txlist` API，按发送方地址逐个拉取样本窗口内交易列表并统计时间间隔。
